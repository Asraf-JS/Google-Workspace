## 7.2 Inspect the Copies

1. Open both exports in available approved viewers.
2. Check the title, contents links, headings, page numbering, tables, images and final paragraph.
3. Record a conversion difference precisely. Correct the source where appropriate, then export again rather than repairing disconnected copies inconsistently.

<summary>What should you see?</summary>

## 7.4 Test Conversion and Issue a Reproducible Release

1. Create a release checklist with Native source, Revision, Export scope, Filename, Viewer and Result. Include the main procedure and any Examples tab or appendix.

2. If using document tabs, inspect the export dialog and deliberately select the required current-tab or all-tabs scope. Make one main-only PDF and one complete handout; if tabs are unavailable, record the appendix scope instead.

3. Export Word and PDF from the checked source. Open them and test three internal links, the contents list, a table and the final procedure paragraph.

4. Create a defect table with source location, export format, observed difference and severity. Record “No difference observed” for each tested element if appropriate; do not invent a defect.

5. For an editable round trip, upload the Word export as a separate practice file and open it in Docs. Keep it clearly distinct from the maintained native source.

6. Compare headings, table structure and links after the round trip. Use document comparison if available for wording, and visual inspection for layout.

7. Change a real instruction in the native source, name the revision, and issue a new checked export with a distinct filename. Retain the earlier release as a labelled prior snapshot.

## Independent Challenge

Close the earlier step lists for the first attempt. Use the case input and your own reasoning. If you need help, record the hint and repeat the affected check independently.

1. Prepare a distribution manifest for an editable handover and a fixed reader copy. State exactly which source revision and tabs/appendices each contains.

2. Have a reviewer identify the current release using only your filenames and manifest. If they choose the wrong one, repair the naming or status label.

3. Demonstrate that the earlier downloaded copy does not change after a native edit, and explain which format would suit each reader.

## Evidence to Hand Over

- Scope-checked PDF/Word copies and a round-trip comparison.
- Element-by-element conversion record, including no-defect findings where observed.
- Release manifest and a checked revised export with an unambiguous current version.

Record the defect or uncertainty you investigated, the evidence used, the repair or reasoned no-change decision, and the final state. Restore temporary changes or keep them in a clearly named scenario copy.

## Troubleshooting

| Symptom | What to check |
|---|---|
| Examples disappear from the complete handout | Check current-tab versus all-tabs export scope, then inspect the end of the new file. |
| An input or earlier result is missing | Reopen the input named in Before You Begin; do not substitute private company data |
| A menu or feature is unavailable | Confirm the account and the shared access notes; record the missing step and ask the trainer for its fallback |
| The result differs from the checkpoint | Compare the exact source range, wording and conditions before repeating the action |
